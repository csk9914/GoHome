# GoHome Design 문서 관리 규칙

> `Docs/Design/`(01·02) 문서의 내용 무결성을 관리하는 규칙이다. 저장소 전체 구조 개요·문서 지도·링크 검증 스크립트는 저장소 루트 [CLAUDE.md](../../CLAUDE.md) 참고 — 이 문서는 Design 문서를 실제로 수정할 때만 읽으면 된다.

**Notion을 가리킬 때는 실제 URL로 링크해도 된다** — 문서명/절 이름 텍스트 언급 대신 URL을 걸면 에이전트/사람 모두 바로 찾아갈 수 있다. 단, `check_doc_links.js`는 md끼리만 검증하므로 이 링크가 깨져도(페이지 이동·삭제) 스크립트가 잡아주지 않는다 — 담당자/일정/DoD를 고칠 때 수동으로 살아있는지 확인할 것.

## 단일 출처 원칙

숫자/결정을 여러 곳에 중복 적지 않는다.

- **인일 추정치**: 유일한 출처는 `02문서`의 "시스템별 요약" 표(1차)와 "13. 2차 프로토타입 추가 시스템"(2차). 다른 문서는 링크만 걸고 숫자를 다시 옮겨 적지 않는다.
- **담당자/일정**: 유일한 출처는 **Notion "GoHome 담당자 배정" DB**. md 쪽(01/02)에는 이 값을 복사해 적지 않고, 필요하면 Notion 링크로 참조한다.
- **아직 결정 안 된 미결 사안**: 유일한 출처는 **Notion "GoHome 착수 로드맵"**. md에는 미결 항목 목록을 두지 않는다.
- **"무엇이 결정됐는지"**: 결정은 그 결정이 실제로 적용되는 01/02문서 절에 직접 쓰고 [표기 관례](#표기-관례)의 라벨(팀 결정/기획 수정/검증 추가)을 단다. 시점 추적은 git log/blame으로 한다.

새 결정/수치가 생기면 이 목록에 없는 새로운 "출처"를 만들지 말고, 위 항목 중 하나에 넣고 나머지 문서에서는 (같은 시스템 안에서만) 링크로, 다른 시스템이면 텍스트 언급으로만 참조할 것.

## 문서 수정 시 확인 절차

1. `node Docs/tools/grep_design_docs.js <키워드>` 로 관련 언급이 있는지 먼저 확인한다. 담당자·일정·DoD 관련 수정이면 Notion 쪽도 확인한다.
2. 위 "단일 출처 원칙"에 따라 실제 값을 고칠 위치를 하나만 정하고, 나머지는 (같은 시스템이면) 링크, (다른 시스템이면) 텍스트 언급만 맞춰준다.
3. 새로운 팀 결정·기획 수정이면 그 결정이 실제로 적용되는 01/02문서 절에 직접 반영하고 [표기 관례](#표기-관례)의 라벨을 단다. 아직 결정 안 된 사안이면 Notion "GoHome 착수 로드맵"에 추가한다.
4. md 헤더 제목을 바꾸거나 삭제했다면 다른 md 문서의 앵커 링크가 깨졌을 수 있다 — 저장소 루트 [CLAUDE.md 검증 스크립트](../../CLAUDE.md#validation-scripts) 절의 `node Docs/tools/check_doc_links.js`를 실행해 오류 0건을 확인한다. **Notion 쪽 변경은 이 스크립트로 검증되지 않으므로**, 담당자/일정/DoD가 바뀌면 01/02의 관련 텍스트 언급이 아직 맞는지 수동으로 확인한다.
5. 인일 추정치를 손댔다면 `node Docs/tools/check_estimate_duplication.js`를 실행해 `02문서` 밖으로 숫자가 새어나가지 않았는지 확인한다.

## 표기 관례

- 원문 대비 변경/추가 사항은 항상 다음 세 라벨 중 하나로 표시한다: **팀 결정**(팀이 명시적으로 정한 것), **기획 수정**(원문 내용을 바꾼 것), **검증 추가**(원문·미션 가이드 재대조로 새로 발견해 채운 것).
- 라벨에 날짜는 적지 않는다(git blame/log가 이미 추적). 특정 시점 내용은 `git log`/`git blame`으로 확인.
- 문서 서술 중 날짜를 꼭 적어야 하는 경우(마감일 등)는 상대적 날짜("다음 주", "이번 주 금요일") 대신 절대 날짜로 적는다.
- 특정 시점의 문서 상태를 통째로 보존해야 하면(예: 제출본) 파일을 복제하지 말고 그 커밋에 `git tag`를 붙인다.
