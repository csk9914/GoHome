## 미션 가이드 원문 요약

> `프로젝트 미션 가이드.docx` 전문 요약 (필수 유저 체험 및 기획 요소):
> 2~4인 협동 / Listen Server / **제한시간 내 목표 점수 달성** / 운반 물품 3종 이상 / **2인 협력 물품·장치** / **환경 방해 요소 2종 이상** / **플레이어 실수로 인한 상호 방해 요소** / 위험-보상 선택 구조 / 성공·실패·재도전 흐름.
> 개발환경: UE5, Git+Git LFS, 대용량 에셋/기획문서는 Google Drive, Blueprint/C++ 자유.

굵게 표시한 네 항목 모두 결정을 완료했다. 충족 여부 표와 근거는 → [03문서 0번 섹션](03_GoHome_리스크_미결정사항.md#0--미션-가이드라인-대조--필수-요건-충족-여부-최우선-검토-필요) 참고.

> **검증 추가 (docx 원문 직접 재대조)**: 위 요약은 원문의 "필수 유저 체험 및 기획 요소" 절만 다뤘다. "필요로 하는 기능과 Asset"·"활용해야 하는 기술"·"레퍼런스" 절까지 재대조한 결과 두 가지 반영 누락을 발견해 수정했다: **제한 시간 카운트다운 UI**(→ [02문서 6절](02_GoHome_기술분석서.md#6-ui))와 **외부 Asset 출처 명시 방식**(→ [03문서 1번](03_GoHome_리스크_미결정사항.md#1-진짜-남은-미결정-항목), 아직 미결정). 원문 레퍼런스는 R.E.P.O./PEAK/Moving Out/Human: Fall Flat이고 "협동 코미디 게임"으로 소개하나, GoHome은 메인 레퍼런스를 머키 다이버즈로, 톤을 "연출 없음"으로 정했다 — 필수 체크리스트 항목은 아니라 급하지 않다. 처리 방침은 [03문서 1번](03_GoHome_리스크_미결정사항.md#1-진짜-남은-미결정-항목) 참고.

## 메인 레퍼런스 확정

> **팀 결정**: GoHome의 메인 레퍼런스는 **머키 다이버즈(Murky Divers)**로 확정한다. 팀원1이 원안에서 명시적으로 참고했고, 딥다이브 프로토콜(팀원0)도 동일하게 지목한 작품이다.

## GoHome 설계 결정의 출처

GoHome 기획서·분석서에 "팀 내 다른 기획안(딥 다이브 프로토콜)"이라고만 적혀 있던 참고 관계를 대조한 요약 (상세 근거·함수명 대조는 각 팀원 원본 문서 참고):

- **AI 상태머신(Enum + Steering Behaviors) · 소음 감지(`GenerateNoise`)** — 팀원3(Abyss Quota) 설계를 함수명까지 그대로 채택
- **소켓 어태치 기반 아이템 홀딩 · `IWeightProvider` 인터페이스 · 장비 강화 구조** — 팀원0(딥다이브 프로토콜)의 패턴 채택
- **도킹 문 개폐 + 몬스터 진입 시 위협 판정** — 팀원0/1/4 공통 모티프("안전지대 입구 on/off")
- **사망 시 관전 모드, 아이템 사망 위치 드롭** — 다수 안 공통 규칙

**GoHome이 채택하지 않은, 딥다이브 프로토콜(팀원0)의 재사용 가능한 설계**:
- `UMultiActorGateComponent` — 두 플레이어가 각자 다른 지점에서 동시 상호작용해야 작동하는 "동시 트리거 게이트". 물리적 공동 운반 없이 2인 협동 요건을 저비용으로 충족하는 패턴. GoHome은 2차 "2인 협동 장치"를 팀원3의 이중 레버 설계로 1순위 채택했지만(→ [01문서 7-1절](01_GoHome_기획서.md#7-1-2인-협동-장치)), 이 컴포넌트도 대안으로 재사용 가능.
- 재접속 지원 설계(PlayerState 그레이스 기간 유지) — GoHome은 범위 밖이지만, 여유가 생기면 참고 가능.

## 팀원 원안 요약

각 안이 미션 필수 요건을 어떻게 구현했는지 요약. GoHome이 2차 프로토타입으로 이연한 세 요건(2인 협동 장치, 목표 점수, 환경 방해 요소 2번째 종류 — 기획 수정으로 추가)에 대한 각 안의 해법을 특히 참고할 만하다.

### 팀원1 — 머키 다이버즈 스타일
- 5인 협동, 라운드제, "경찰"(추격형 위협)이 타이머 임박 시 등장하는 연출형 압박 시스템.
- 크레딧 목표치가 미션 가이드의 "목표 점수" 요건을 충족.
- 2인 협동은 "동료 구조"(붙잡힌 팀원을 상호작용으로 구출) 정도로만 약함 — 강제 2인 협동 장치는 없음.

### 팀원2 — 아틀란티스 유적 탐사
- 거대 석상 2인 운반(밸런스 게이지), 구출 시스템(버튼 연타), 유적 붕괴 시스템(왕복 위험도 상승형 점수제) 제안 — 메커닉 자체는 미채택.
- **맵 컨셉(아틀란티스)**: 기획 수정으로 GoHome 1차 맵 컨셉("탁 트인 아틀란티스")만 채택. 배경만 가져오고, 2인 협동은 동시 트리거 게이트(팀원3안), 위험-보상은 소음 유발형 아이템·목표 점수 시스템으로 별도 구현 (→ [01문서 8-1절](01_GoHome_기획서.md#8-1-1차-프로토타입-맵--아틀란티스튜토리얼)).

### 팀원3 — Abyss Quota
- GoHome의 AI/소음 시스템 설계 원본 (→ [GoHome 설계 결정의 출처](#gohome-설계-결정의-출처)).
- **이중 레버 봉인문**: 두 플레이어가 각자 떨어진 레버를 3초 안에 동시 작동해야 열리는 2인 협동 장치 — 상태머신(Idle→Armed→Success/Failed→Open→Cooldown)까지 구체 설계됨. GoHome이 2차 프로토타입 2인 협동 장치로 채택.
- **수류 구간**(8절 "환경 방해 요소"): 방향력이 작용하는 구역, 무거운 물품일수록 더 밀리는 설계 — GoHome이 환경 방해 요소 2번째 종류로 채택, 기획 수정으로 **2차 프로토타입**에 추가 (→ [01문서 7-3절](01_GoHome_기획서.md#7-3-환경-방해-요소-2번째-종류-수류-구간)).
- 수심별 목표 점수(할당량) 시스템 존재.

### 팀원4 — Game Design Document
- 미션 가이드 요건을 항목별로 표로 대조하며 작성된 가장 체계적인 안.
- **환경 방해 요소**(2.2절, 4.2절): 지뢰형 트랩·당기기/밀치기 함정·전류 트랩·먹물 트랩·자동문·협동 오픈 기믹·알람 트랩·느려지는 공간 8종. 이 중 **느려지는 공간(수류 구간 계열)이 GoHome에 채택**(기획 수정, 2차 추가 항목, → [02문서 13-3](02_GoHome_기술분석서.md#13-3-환경-방해-요소-2번째-종류-수류-구간)). 4.2절의 "PhysicsVolume의 FluidFriction/ZoneVelocity로 대부분 커버" 메모가 저비용 근거.
- **플레이어 간 상호 방해**(2.3절): 충돌 시 아이템 드랍·몸으로 막기·무게차 밀치기·손전등 시야 노출 등 8종 제안. GoHome의 채택 방식(신규 시스템 없이 캐릭터 충돌+도킹 문)과 근거는 [01문서 3-7절](01_GoHome_기획서.md#7-플레이어-간-상호-방해--신규-시스템-없이-1차에-포함-검증-추가-팀-결정)이 단일 출처. 아이템 드랍/무게차 밀치기는 여유 생기면 재검토 후보.
- **협동 오픈 기믹**: 한 명이 발판에 서 있어야 문이 열리고 이탈 시 서서히 닫히는 방식 — 동시 트리거 게이트보다 단순한 2인 협동 대안(팀원3 이중 레버가 1순위, 단순화 필요 시 검토).
- **재화 완전 공유형 + 라운드별 최소 정산 금액**(할당량 증가형) — 목표 점수 요건의 또 다른 구체 사례.
- 4.2절에 넉백/순간 이동 계열 리플리케이션 리스크를 미리 정리해 둔 점이 유용(GoHome 4번 시스템 검토 시 참고 가치).

## 딥다이브 프로토콜(팀원0)이 GoHome과 다른 점

딥다이브 프로토콜은 GoHome과 별도로 완결된 3개월·5인 규모 기획(코즈믹 호러 톤, 심도 3단계, 서핏 크루 협동, 재접속 지원 포함)이다. GoHome은 기술적 패턴(소켓 어태치, 인터페이스 최소화, 업그레이드 구조)만 차용한다 — 콘텐츠 요소 미채택 범위는 [01문서 6절](01_GoHome_기획서.md#6-이번-범위1차에서-하지-않는-것)이 단일 출처.
